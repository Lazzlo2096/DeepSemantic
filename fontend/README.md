# Каталог статей arXiv

Из корня DeepSemantic запусти `docker compose up -d fontend` и открой страницу каталога. При необходимости порт задаётся переменной `FONTEND_PORT`. [Локальный каталог](http://127.0.0.1:8080)

## Развёртывание на deep-semantic.com

На Ubuntu запусти `sudo bash bootstrap.sh` из корня проекта. Запись DNS для `deep-semantic.com` должна указывать на публичный адрес сервера, а TCP-порты 80 и 443 должны быть свободны и доступны из интернета. Caddy выпустит и будет обновлять сертификат автоматически. [Каталог на сервере](https://deep-semantic.com)

Укажи в `.env` ключ `OPENROUTER_API_KEY` и выбери модели `RAG_OPENROUTER_MODEL` и `SUMMARY_OPENROUTER_MODEL`. Затем запусти `sudo just up-server`. Генерация и эмбеддинги выполняются через OpenRouter.

Управление воркерами доступно без пароля через публичную страницу. [Воркеры на сервере](https://deep-semantic.com/workers.html)

## Работа с каталогом

Страница читает `GET /papers` через локальный прокси Caddy и показывает заголовки, авторов, даты подачи и аннотации. Каталог показывает по 12 записей на странице и общее число страниц для выбранных фильтров.

Заголовок в каталоге и результатах поиска открывает страницу статьи со всеми чанками в исходном порядке. Страница читает данные статьи из `GET /papers/{arxiv_id}` и её чанки из `GET /papers/{arxiv_id}/chunks`. Ссылка «arXiv ↗» рядом с заголовком открывает оригинал в новой вкладке.

`summary-worker` автоматически создаёт задание для статьи, когда доступен Markdown. Кнопка «Суммаризировать» также позволяет запустить его вручную. Страница опрашивает `GET /papers/{arxiv_id}/summary` и показывает прогресс или сохранённый результат на русском. Повторный запрос возвращает существующее задание или готовый результат. После ошибки кнопка «Повторить» ставит задание заново.

`summary-worker` читает полный Markdown из RustFS и отправляет его вместе с промптом одним запросом. Промпт запрашивает объяснение на русском объёмом 700–1000 слов и шесть разделов от главной идеи до практического значения. Для суммаризации нужен импорт в режиме HTML.

Для суммаризации, ответов RAG и эмбеддингов укажи `OPENROUTER_API_KEY` в `.env`. Модель для RAG задаётся через `RAG_OPENROUTER_MODEL`, по умолчанию `deepseek/deepseek-v4.1-flash-1017`. Для суммаризации можно задать `SUMMARY_OPENROUTER_MODEL` и `SUMMARY_OPENROUTER_REASONING_EFFORT`. Если модель суммаризации не задана, воркер берёт модель RAG. В `.env.example` для воркера указаны `deepseek/deepseek-v4-pro-0813` и `high`. После изменения `.env` пересоздай соответствующий контейнер.

Для суммаризации через OpenRouter действуют лимиты провайдера. PostgreSQL хранит статус и итоговый Markdown в `paper_summaries`, по одной записи на версию статьи.

При обновлении работающего стека с `paper-summarizer` сначала выполни `docker compose down --remove-orphans` с тем же набором Compose-файлов, затем запусти проект в своём режиме. Тома и задания суммаризации сохранятся.

Сортировку можно выбрать по времени загрузки, дате подачи или этапу обработки. Фильтры по статусу и дате подачи можно использовать вместе. Границы диапазона включаются целиком по UTC. API принимает `sort` (`downloaded_desc`, `submitted_desc`, `submitted_asc`, `status`), `status`, `date_from` и `date_to` (`ГГГГ-ММ-ДД`).

Каталог сохраняет фильтры, сортировку и номер страницы в URL, например `/?status=texted&sort=submitted_desc&page=2`. Ссылка с `query` сразу запускает поиск в режиме из параметра `mode` (`vector`, `text` или `rag`). Без `mode` используется поиск по RAG. Кнопка «Вернуться к каталогу» восстанавливает параметры каталога.

- «Поиск по RAG» отправляет запрос в `POST /rag/answer`. Модель вызывает векторный или текстовый поиск и читает исходный текст статьи или суммаризации по координатам. Контекст и объём генерации определяются настройками модели и провайдера. Ответ показывает ссылки на подтверждающие фрагменты и пояснение их выбора. Блок «Как найден ответ» обновляется примерно раз в секунду и показывает завершённые шаги модели, доступный текст рассуждения от провайдера и карточки инструментов с аргументами, результатами и временем. Ссылка на запуск открывает сохранённую историю через `GET /rag/runs/{run_id}`. Выбранная модель должна поддерживать вызов инструментов и структурированный вывод.
- «Векторный поиск по эмбеддингам» вызывает `POST /chunks/search` и показывает похожие фрагменты с оценкой сходства.
- «Текстовый поиск» вызывает `POST /chunks/search/text`. PostgreSQL ищет введённую строку без учёта регистра внутри сохранённых чанков. Поиск доступен после разбиения текста на чанки, даже если для них ещё нет эмбеддингов.

На странице «Импорт arXiv» можно отправить `POST /arxiv/imports` с диапазоном дат и необязательным фильтром. API выбирает бакет по умолчанию. История из `arxiv_imports` читается через `GET /arxiv/imports`, показывает статус, попытки и результаты и обновляется каждые пять секунд на открытой вкладке. [Импорт arXiv](http://127.0.0.1:8080/imports.html)

Команды `just up` и `just up-server` создают контейнеры воркеров без запуска. Скачивание, извлечение текста, индексацию и суммаризацию можно включить кнопкой «Старт» на странице «Воркеры». Статусы Docker обновляются каждые пять секунд. [Воркеры](http://127.0.0.1:8080/workers.html)
