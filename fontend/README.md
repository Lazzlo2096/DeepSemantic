# Каталог статей arXiv

Из корня DeepSemantic запусти `docker compose up -d fontend` и открой страницу каталога. При необходимости порт задаётся переменной `FONTEND_PORT`. [Локальный каталог](http://127.0.0.1:8080)

Страница читает `GET /papers` через локальный прокси Caddy и показывает заголовки, авторов, даты подачи и аннотации. Каталог показывает по 12 записей на странице и общее число страниц для выбранных фильтров.

Заголовок в каталоге и результатах поиска открывает страницу статьи со всеми чанками в исходном порядке. Страница читает данные статьи из `GET /papers/{arxiv_id}` и её чанки из `GET /papers/{arxiv_id}/chunks`. Ссылка «arXiv ↗» рядом с заголовком открывает оригинал в новой вкладке.

На странице статьи с доступным полным текстом кнопка «Суммаризировать» ставит фоновое задание через `POST /papers/{arxiv_id}/summary`. Страница опрашивает `GET /papers/{arxiv_id}/summary` и показывает прогресс или сохранённый результат на русском. Повторный запрос возвращает существующее задание или готовый результат. После ошибки кнопка «Повторить» ставит задание заново.

Сервис `summary-worker` собирается в отдельный образ и запускается вместе с проектом. Он читает полный текст из RustFS и использует тег Gemma 3 из `OLLAMA_MODEL`. Размер рабочего контекста задаёт `SUMMARY_CONTEXT_TOKENS` (по умолчанию 4096). Если полный запрос с резервом для ответа превышает этот бюджет, воркер делит текст на части в памяти и объединяет их выжимки. PostgreSQL хранит статус и итоговый JSON в `paper_summaries`, по одной записи на версию статьи.

При обновлении работающего стека с `paper-summarizer` сначала выполни `docker compose down --remove-orphans` с тем же набором Compose-файлов, затем запусти проект в своём режиме. Тома и задания суммаризации сохранятся.

Сортировку можно выбрать по времени загрузки, дате подачи или этапу обработки. Фильтры по статусу и дате подачи можно использовать вместе. Границы диапазона включаются целиком по UTC. API принимает `sort` (`downloaded_desc`, `submitted_desc`, `submitted_asc`, `status`), `status`, `date_from` и `date_to` (`ГГГГ-ММ-ДД`).

Каталог сохраняет фильтры, сортировку и номер страницы в URL, например `/?status=chunked&sort=submitted_desc&page=2`. Ссылка с `query`, например `/?query=neural+networks`, сразу запускает поиск по смыслу. Кнопка «Вернуться к каталогу» убирает `query` из URL и восстанавливает параметры каталога.

Поле «Поиск по смыслу» отправляет запрос в `POST /chunks/search`. API принимает `query` и необязательный `limit` от 1 до 50 (по умолчанию 10). Результаты содержат текст чанка, оценку сходства и данные статьи, если она связана с чанком. Векторы для поиска автоматически добавляет сервис `paper-indexer`.

На странице «Импорт arXiv» можно отправить `POST /arxiv/imports` с диапазоном дат и необязательным фильтром. API выбирает бакет по умолчанию. История из `arxiv_imports` читается через `GET /arxiv/imports`, показывает попытки, результаты и ошибки и обновляется каждые пять секунд на открытой вкладке. [Импорт arXiv](http://127.0.0.1:8080/imports.html)

На странице «Воркеры» можно запускать и останавливать созданные Compose-контейнеры импорта, индексации, суммаризации и BGE-M3. Статусы Docker обновляются каждые пять секунд на открытой вкладке. Чтобы создать контейнеры, запусти проект в своём режиме через `just up`, `just up-gpu` или `just up-amd`. В режиме AMD воркер BGE-M3 управляется в Windows. [Воркеры](http://127.0.0.1:8080/workers.html)
