# PostgreSQL

Запуск из корня проекта через `docker compose up -d postgres` или `just up`. Данные сохраняются в томе `postgres-data`.

Контейнеры Compose подключаются по адресу `postgres:5432`. Имя базы, пользователь и пароль для локального запуска по умолчанию — `deepsemantic`. Перед первой инициализацией их можно задать через `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD`.

Открыть `psql` с настройками контейнера можно командой:

```sh
docker compose exec postgres sh -c 'exec psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## pgAdmin

Запустите `docker compose up -d pgadmin` и откройте http://127.0.0.1:5050. Для первого входа по умолчанию используются `admin@deepsemantic.dev` и пароль `deepsemantic`. Их можно задать через `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD` перед инициализацией тома `pgadmin-data`.

При первой инициализации pgAdmin импортирует **DeepSemantic PostgreSQL** из `pgadmin/servers.json`. При подключении введите пароль PostgreSQL. Если имя базы или пользователя отличается от значения по умолчанию, укажите его в настройках подключения.

В уже инициализированном pgAdmin файл можно загрузить через **Tools → Import/Export Servers**, сохранив существующие подключения.

## Миграции

Ревизии Alembic лежат в `postgres/migrations/versions/`. При запуске через `just up` сервис `migrate` выполняет `alembic upgrade head` после готовности PostgreSQL. API запускается после успешного завершения миграций. Первые две ревизии поддерживают и пустую базу, и таблицу, которую ранее создавал API.

Проверить текущую ревизию можно командой `docker compose run --rm migrate current`.

## Счётчики задания импорта arXiv

`arxiv_import_result` принимает ID задания из `POST /arxiv/imports` и возвращает одну строку со счётчиками из `arxiv_import_attempts`. API возвращает счётчики в поле `result` и прогресс в `processed_articles` в `GET /arxiv/imports`.

```sql
SELECT * FROM arxiv_import_result('6f9619ff8b86d011b42d00c04fc964ff'::uuid);
```

- `articles_found` — число найденных версий статей, включая повторяющиеся ID.
- `pdf_available` — исходники, которые воркер скачал или нашёл в бакете задания.
- `pdf_reused` — исходники из `pdf_available`, которые уже были в бакете при проверке.
- `pdf_failures` — ошибки при скачивании исходников.
- `html_unavailable` — статьи, которые arXiv явно пометил как недоступные в HTML.
- `processed_articles` — число обработанных статей в текущей попытке, если поиск завершился.

Счётчики отражают последнюю попытку, для которой воркер сохранил результаты поиска. Если у задания ещё нет результата, функция возвращает пустую выборку. Если поиск завершился без статей, функция возвращает строку с нулевыми счётчиками.

## Счётчики каталога arXiv

`arxiv_catalog_result` возвращает JSONB с полем `pdf_available`. Функция считает записи в `arxiv_papers` по бакету и датам первой подачи в UTC, включая обе даты:

```sql
SELECT arxiv_catalog_result(DATE '2026-11-02', DATE '2026-11-03', 'arxiv-papers');
```

Это срез текущего каталога: он включает записи предыдущих импортов и не проверяет наличие файлов в RustFS. Счётчик каталога учитывает бакет и даты. Для счётчиков отдельного задания используйте `arxiv_import_result`.

## Чанки

В таблице `chunks` хранятся `id`, текст чанка `text` и время создания `created_at`. Миграция переименовывает `documents` с сохранением строк и их ID. Маршруты `/chunks` работают с таблицей `chunks`.

Поля `qdrant_collection` (`text`) и `qdrant_point_id` (`bigint`) предназначены для ссылки на точку в Qdrant. Пока ссылка не записана, оба поля имеют значение `NULL`.

Таблица `paper_chunks` связывает чанк со статьёй и хранит тип источника (`article` или `summary`). Нумерация `chunk_index` начинается с нуля для каждого источника. Представление `current_paper_chunks` показывает чанки актуальной версии источника.

`source_start` и `source_end` задают диапазон `[start, end)` в символах Unicode исходного текста, считая с нуля. Для статьи отсчёт идёт по декодированному UTF-8-файлу из RustFS после удаления BOM, для суммаризации — по `paper_summaries.summary`. Для преобразованной таблицы диапазон охватывает исходные HTML-строки, из которых собран фрагмент. У старых чанков значения остаются `NULL` до обработки воркером.

Отправьте `POST /chunks` с телом `{"text":"Текст для индексации"}`. Успешный запрос возвращает `201 Created` с полями `id` и `created_at`. Пустой или пробельный текст возвращает `422`. Построение эмбеддинга выполняется отдельным вызовом. [Swagger UI](http://127.0.0.1:8000/docs)

- `GET /chunks/{chunk_id}` возвращает `id`, `text`, `created_at`, `qdrant_collection` и `qdrant_point_id`. До индексации оба поля Qdrant возвращаются как `null`. Если чанк отсутствует, API возвращает `404`.
- `GET /chunks?limit=20&offset=0` возвращает массив чанков с теми же полями в порядке возрастания `id`. `limit` принимает значения от 1 до 100, `offset` задаёт число пропускаемых записей. Пустая страница возвращает `[]`.
- `GET /chunks/{chunk_id}/embedding` возвращает сохранённый в Qdrant эмбеддинг как JSON-массив. Если чанк или его точка отсутствует, API возвращает `404`.
- `POST /chunks/{chunk_id}/embedding` строит эмбеддинг и записывает его в коллекцию источника для выбранного провайдера и модели с ID чанка в качестве ID точки. После подтверждения записи в Qdrant сервис заполняет `qdrant_collection` и `qdrant_point_id` в PostgreSQL и возвращает вектор как JSON-массив. Повторный запрос с той же моделью обновляет ту же точку. Для отсутствующего чанка возвращается `404`, при превышении лимитов модели — `422`.

После включения на странице «Воркеры» сервис `embeding-worker` разбивает на чанки извлечённый текст статьи из RustFS и завершённую суммаризацию из PostgreSQL. Эмбеддинги текста статьи и вручную созданных чанков хранятся в `documents_bge_m3`, эмбеддинги суммаризаций — в `paper_summaries_bge_m3`. Поиск по смыслу запрашивает обе коллекции. После каждого прохода воркер ждёт 15 секунд. Прогресс виден в `docker compose logs -f embeding-worker`.

Для разового прохода при остановленном `embeding-worker` можно запустить из корня проекта:

```sh
docker compose run --rm --no-deps embeding-worker python -m paper_embeddings
```

Команда отправляет ещё не индексированные чанки пакетами по восемь. После подтверждения записи в Qdrant она сохраняет ссылки в PostgreSQL. Повторный запуск продолжает с оставшихся чанков. Если модель отклоняет отдельный чанк, команда пишет его ID в журнал и продолжает с остальными. При ошибках команда завершается с ненулевым кодом.
