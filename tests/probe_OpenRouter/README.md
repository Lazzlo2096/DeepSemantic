# OpenRouter embeddings probe

Из этой папки можно использовать `just`:

```powershell
just check
just dry-run
just smoke
just run
just run --batch-sizes 8 16 --concurrency 1 2 --repeats 2
```

`smoke` и `run` отправляют платные API-запросы. Из корня репозитория:
`just --justfile tests/probe_OpenRouter/justfile dry-run`.

Измеряет обычный синхронный `/embeddings` с массивом текстов, не асинхронный Batch API.
Работает напрямую с OpenRouter, независимо от RabbitMQ и сервисов проекта.

Команды из корня репозитория. Ключ и модель берутся из корневого `.env`:

```powershell
docker compose --env-file .env -f tests/probe_OpenRouter/compose.yaml run --build --rm probe --dry-run
```

Небольшой платный прогон, 16 чанков, два размера пакета:

```powershell
docker compose --env-file .env -f tests/probe_OpenRouter/compose.yaml run --build --rm probe --output /results --chunks 16 --batch-sizes 1 8 --concurrency 1 --repeats 1
```

Полная матрица: батчи 8/16/32/64/128 × параллельность 1/2/3/4 × три повтора.
Каждый вариант обрабатывает те же 960 синтетических чанков: 60 прогонов,
2796 HTTP-запросов и всего 57 600 отправленных чанков.
При батче 128 последний пакет содержит 64 чанка. Даже для батча 128
получается восемь запросов на прогон, что позволяет проверить параллельность 4.
Если нужны только полные пакеты для всех размеров, укажи `--chunks 1024`.

```powershell
docker compose --env-file .env -f tests/probe_OpenRouter/compose.yaml run --build --rm probe
```

Собственные данные: положи JSON-массив строк в `data/chunks.json` и добавь
`--output /results --input /data/chunks.json` после `probe`.
Переданные после имени сервиса аргументы заменяют `command` Compose, поэтому при своих
аргументах указывай `--output /results`, чтобы сохранить результат на хосте.

В скрипте закреплён только DeepInfra (`provider.only = ["deepinfra"]`),
fallback выключен. Если DeepInfra недоступен, запрос завершится ошибкой без переключения на другого провайдера.
Размеры пакетов и длины текстов должны соответствовать ограничениям выбранной модели/провайдера.

Результаты сохраняются в `results/<UTC timestamp>/`:

- `metadata.json`: настройки и размер входных данных;
- `requests.jsonl`: время каждого запроса, HTTP-статус, usage и сведения модели/провайдера, если они возвращены;
- `summary.csv` и `summary.json`: метрики каждого варианта и повтора.

Скорость — успешно обработанные чанки / полное время варианта, включая ошибки.
Медиана и p95 — время успешных HTTP-запросов без ожидания свободного места у клиента.
Вектора и тексты в результатах не сохраняются. Автоматических повторов запросов нет:
429, таймауты и другие ошибки учитываются в отчёте.
Порядок вариантов перемешивается воспроизводимо (`--seed 42`); между ними пауза 3 секунды.
Прогрев не отделён, поэтому первый запрос может включать установку соединения.
Сравнивай скорость вместе с ошибками и несколькими повторами; синтетические тексты
нужны для проверки инструмента, для рабочих выводов используй реальные чанки.

Локально: `python -m pip install -r tests/probe_OpenRouter/requirements.txt`, затем
`python tests/probe_OpenRouter/probe.py --dry-run`. Для API-вызовов задай
`OPENROUTER_API_KEY` в окружении; локальный скрипт сам `.env` не читает.
