# Журнал изменений DeepSemantic

## [2026-11-22] - Nemotron 3.5 Embed через OpenRouter

- Провайдер эмбеддингов по умолчанию переключён на OpenRouter, модель — `nvidia/nemotron-3.5-embed-8b:free`.
- Обновлены Compose, env-шаблон, Temporal fingerprint, probe и проверки 4096-мерного ответа. Индексация передаёт `search_document`, поиск — `search_query`; воркер разбиения использует закреплённый токенизатор Nemotron.
- Локальный DeepKaravan/BGE-M3 сохранён как явно выбираемая конфигурация со своим токенизатором.

## [2026-11-15] - Локальные эмбеддинги через DeepKaravan

- Подключён сабмодуль DeepKaravan: основной Docker Compose запускает локальный сервис эмбеддингов BGE-M3 на CPU с отдельным томом для кеша модели, без публикации порта.
- Добавлен `api/embedding_service.py` — общая прослойка доступа к эмбеддингам для API, RAG и воркеров. Она направляет запросы в DeepKaravan или OpenRouter по `EMBEDDING_PROVIDER=deepkaravan|openrouter`, выбирает адрес API и настраивает авторизацию без изменения прикладного кода. По умолчанию используется DeepKaravan без API-ключа, для OpenRouter требуется `OPENROUTER_API_KEY`. Адрес можно переопределить через `EMBEDDING_BASE_URL`.
- Контейнер DeepKaravan включается профилем Compose только при выборе локального провайдера. Обновлены команды `just`, примеры env и инструкции; при переходе на облако уже работающий локальный контейнер нужно остановить отдельно.
- Сохранены существующие идентификаторы модели и коллекции эмбеддингов. RAG и суммаризация продолжают использовать OpenRouter.
- Добавлены проверки обоих провайдеров, авторизации, настройки адреса и таймаута, а также профилей Compose и команд запуска. Все 37 тестов проходят.

## [2026-11-15] - Temporal как единственный владелец состояния обработки

- Удалены SQL-журнал заданий, таблицы попыток и прогресса импорта, поля статусов, аренды и повторов у импортов, статей и саммари.
- API запускает workflow напрямую, отправляет Signal паузы и получает Query прогресса. SQL-диспетчер удалён.
- PostgreSQL сохраняет параметры запросов, статьи, готовые саммари и чанки. Манифест импорта хранится в RustFS, курсоры и счётчики — в Temporal.
- Миграция `0039_temporal_native_state` требует остановки старого стека и завершения либо явного прекращения старых workflow. Сохранённые тексты саммари остаются в БД.


## [2026-11-15] - Фоновые задания на Temporal

- Импорт, извлечение текста, суммаризация и индексация переведены с SQL-аренд и циклов опроса на Temporal Workflows и Activities. API и имена четырёх воркеров сохранены.
- Добавлены журнал доставки `temporal_jobs`, стабильные Workflow ID, сохранение списка статей и курсора индексации, Continue-As-New и повтор неуспешных заданий.
- Саммари привязаны к версии входного Markdown; устаревшие результаты исключаются из поиска и не могут заменить новые запросы.
- Добавлены Temporal Server, UI, отдельный PostgreSQL и его резервное копирование. Миграция `0038` требует остановленных старых воркеров; обновление описано в `temporal/README.md`.
- Добавлены изолированные интеграционные проверки с настоящими Temporal и хранилищами; платные вызовы модели подменены.

## [2026-11-14] - Подключение LangSmith Studio

- Добавлен отдельный сервис `studio` в Docker Compose и команды `just studio-up`, `studio-down`, `studio-logs`.
- Граф RAG доступен в Studio через Agent Server: визуализация, просмотр промежуточного состояния, остановки и продолжение выполнения. Для ввода вопроса используется поле `question`.
- Узлы и переходы поиска общие с API; адаптер подготавливает контекст и сохраняет состояние в формате, совместимом с checkpoints. История Studio хранится в отдельном Docker volume, облачная трассировка отключена.
- Добавлены проверки схемы, восстановления состояния, повторных вопросов и освобождения ресурсов. Существующий журнал запусков сайта сохранён.

## [2026-11-13] - RAG на LangChain и LangGraph

- Ручной цикл поиска заменён графом LangGraph с узлами сбора источников, выполнения инструментов и формирования ответа.
- Вызовы модели RAG выполняются через LangChain `ChatOpenRouter`, инструменты — через `StructuredTool`, ответ запрашивается с JSON Schema.
- Сохранены два промпта, поиск по статьям и суммаризациям, проверка ссылок, журнал шагов и существующий контракт API.
- Обновлены зависимости и Docker-сборка API. Добавлены проверки графа с подставными ответами OpenRouter; все 22 теста проходят на Windows и в Linux-контейнере.

## [2026-11-12] - Переход на облачный инференс через OpenRouter

- Полностью отказались от локального инференса в пользу облачного через OpenRouter: генерация ответов RAG, суммаризация и эмбеддинги выполняются через его API.
- Удалены Ollama, локальный `embeding-service`, GPU-конфигурации и зависимости для локального инференса. API и воркер индексации запрашивают эмбеддинги напрямую у OpenRouter.
- Обновлены конфигурации запуска, переменные окружения, интерфейс управления воркерами и документация.

## [2026-11-10] - RAG с инструментами поиска

- Режим «Поиск по RAG» на главной странице отправляет запрос в LLM. Модель сама выбирает векторный поиск, буквальный поиск по тексту или чтение исходного документа.
- Оба инструмента поиска возвращают текст чанка и координаты в документе. Векторный поиск также возвращает оценку сходства.
- Инструмент чтения возвращает до 1500 символов статьи или суммаризации по ID и диапазону `[source_start, source_end)`. В ответе RAG отображаются ссылки на использованные фрагменты и их координаты.

## [2026-11-08] - Импорт HTML из arXiv

- Воркер выбирает формат источника через `ARXIV_SOURCE_FORMAT=pdf|html`. По умолчанию используется PDF с извлечением текста через `pypdf`.
- В режиме HTML воркер сохраняет исходную страницу и Markdown в RustFS. Markdown включает заголовки, формулы LaTeX, таблицы, подписи и ссылки на рисунки.
- Markdown-фрагменты сохраняются в `chunks.text` с переносами строк. При успешной смене формата для уже загруженной статьи воркер заменяет её чанки.
