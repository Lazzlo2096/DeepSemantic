# arXiv Grabber

## Запуск через API

Из корня проекта запустите `just up` или обновите миграции, API и воркер командой `docker compose up -d --build migrate api arxiv-grabber`. При переходе со старой версии сначала остановите старый API и дождитесь, пока старый воркер обработает ожидающие и неподтверждённые сообщения в RabbitMQ `arxiv.imports`.

```powershell
$body = @{
    date_from = '2023-06-05'
    date_to = '2023-06-06'
    query = 'cat:cs.AI'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/arxiv/imports' `
    -ContentType 'application/json' -Body $body
```

`POST /arxiv/imports` принимает даты в формате `YYYY-MM-DD`, необязательные `bucket` и `query`. API возвращает `202 Accepted` и `{"id":"…"}` после записи задания в PostgreSQL `arxiv_imports`. При неверных параметрах API возвращает `422`, при недоступности PostgreSQL — `503`.

Воркер `arxiv-grabber` проверяет PostgreSQL каждые три секунды, пока очередь пуста. При старте задания он ставит `running` и продлевает двухминутную аренду каждые 30 секунд. После истечения аренды задание можно взять повторно. При ошибке обработки воркер повторяет задание через минуту. Максимум три попытки. Итоговые статусы `completed` и `failed`, счётчики и последнюю ошибку можно посмотреть в `arxiv_imports` по ID из ответа API. Тот же ID используется в `docker compose logs arxiv-grabber`. `completed` означает завершение импорта до этапа чанков. Эмбеддинги строятся отдельным воркером.

Маршрут также доступен в [Swagger UI](http://127.0.0.1:8000/docs).

Во время обработки `result.articles_found` показывает число статей на уже просмотренных страницах arXiv, а `result.pdf_reused` — сколько проверенных PDF уже было в выбранном бакете RustFS. Счётчики относятся к текущей попытке и видны на странице импорта до её завершения.

## Запуск через CLI

Команда для прямого импорта из корня `DeepSemantic`.

```sh
docker compose run --build --rm arxiv-grabber --from 2023-06-05 --to 2023-06-05 --query 'cat:cs.AI'
```

Обе даты включены. Отбор идёт по дате первой подачи статьи на arXiv в UTC. При пустом фильтре берутся все категории. Бакет по умолчанию — `arxiv-papers`, его можно изменить переменной `RUSTFS_BUCKET`.

PDF сохраняются под ключом `arxiv/<arxiv_id>.pdf`, где `arxiv_id` включает версию статьи. Уже существующий объект используется повторно. Если отдельный PDF не загрузился, скрипт обрабатывает оставшиеся статьи и возвращает код `1`. Повторный запуск проверяет наличие объектов и догружает пропущенные PDF.

При импорте воркер извлекает текст со всех страниц и сохраняет его в UTF-8 под ключом `arxiv/<arxiv_id>.txt` в том же бакете. Для ранее скачанных PDF достаточно повторить импорт за нужный диапазон. Воркер использует готовый текст, если он относится к тому же PDF. Для PDF без текстового слоя требуется OCR. При ошибке извлечения воркер сохраняет запись о PDF, оставляет `text_object_key` пустым и сообщает об ошибке в логе. [Документация по извлечению текста](https://pypdf.readthedocs.io/en/stable/user/extract-text.html).

После сохранения `.txt` воркер сводит пробельные последовательности к одному пробелу и делит текст на чанки по 1000 символов. Перекрытие соседних чанков составляет 150 символов, то есть 15% полного чанка. Последний чанк может быть короче. Текст чанков хранится в `chunks`, а связь со статьёй и позиция с нуля — в `paper_chunks`. Повторный импорт той же версии статьи использует существующий набор чанков.

## Каталог в pgAdmin

Каталог также доступен через API. `GET /papers?limit=20&offset=0` возвращает последние загрузки, `limit` принимает значения от 1 до 100. `GET /papers/{arxiv_id}` возвращает запись указанной версии статьи. Например, `GET /papers/2611.07253v1`. [Swagger UI](http://127.0.0.1:8000/docs#/papers)

Откройте **DeepSemantic PostgreSQL → Databases → deepsemantic → Schemas → public → Tables → arxiv_papers**. Если pgAdmin уже открыт, обновите узел **Tables**. [pgAdmin](http://127.0.0.1:5050)

```sql
SELECT arxiv_id, title, submitted_at, bucket, object_key, text_object_key, downloaded_at
FROM public.arxiv_papers
ORDER BY downloaded_at DESC, arxiv_id;
```

Строка появляется после подтверждения, что PDF есть в RustFS. `arxiv_id` включает версию статьи и является первичным ключом. `submitted_at` — дата и время первой подачи, `downloaded_at` — время загрузки объекта в бакет по данным RustFS. `text_object_key` указывает на текстовый файл в `bucket` и заполняется после его сохранения. При импорте той же версии в другой бакет каталог указывает на копию с более свежим `downloaded_at`. При равенстве времени выбирается бакет, который идёт первым по имени.

Запросы к arXiv выполняются последовательно с интервалом не менее трёх секунд. Для массовой загрузки архивов arXiv предоставляет [доступ к PDF через S3](https://info.arxiv.org/help/bulk_data_s3.html). [Руководство по API arXiv](https://info.arxiv.org/help/api/user-manual.html) · [Условия использования API](https://info.arxiv.org/help/api/tou.html).
