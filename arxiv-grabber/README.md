# arXiv Grabber

## Запуск через API

Из корня проекта запустите `just up` или обновите миграции, API и воркер командой `docker compose up -d --build migrate api arxiv-grabber`. При переходе со старой версии сначала остановите старый API и дождитесь, пока старый воркер обработает ожидающие и неподтверждённые сообщения в RabbitMQ `arxiv.imports`.

Перед применением миграции `0019_drop_arxiv_import_result` дождитесь окончания текущего импорта и выполните `docker compose stop api arxiv-grabber`. Затем запустите миграции и новые версии сервисов командой выше.

```powershell
$body = @{
    date_from = '2023-06-05'
    date_to = '2023-06-06'
    query = 'cat:cs.AI'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/arxiv/imports' `
    -ContentType 'application/json' -Body $body
```

`POST /arxiv/imports` принимает даты в формате `YYYY-MM-DD`, необязательные `bucket` и `query`. API возвращает `202 Accepted` и `{"id":"…"}` после записи задания в PostgreSQL `arxiv_imports`. При неверных параметрах API возвращает `422`, при недоступности PostgreSQL — `503`.

Воркер `arxiv-grabber` проверяет PostgreSQL каждые три секунды, пока очередь пуста. При старте задания он ставит `running` и продлевает двухминутную аренду каждые 30 секунд. После истечения аренды задание можно взять повторно. При ошибке обработки воркер повторяет задание через минуту. Максимум три попытки. Статус задания хранится в `arxiv_imports`. Подробности ошибок доступны в `docker compose logs arxiv-grabber` по ID из ответа API. `completed` означает завершение импорта до этапа чанков. Эмбеддинги строятся отдельным воркером.

Маршрут также доступен в [Swagger UI](http://127.0.0.1:8000/docs).

`GET /arxiv/imports` заполняет `result` из `arxiv_import_result(id)`. Счётчики отражают текущее состояние каталога после сохранения списка кандидатов. У заданий без сохранённого списка `result` равен `null`.

После получения всех страниц воркер записывает в `arxiv_imports.candidate_arxiv_ids` массив `text[]` с ID найденных версий статей. Это происходит до первой проверки исходников в RustFS, поэтому уже скачанные статьи тоже попадают в список. `NULL` означает, что список ещё не записан, а `{}` — что поиск завершился без результатов. При повторной попытке список заменяется после успешного поиска.

## Запуск через CLI

Команда для прямого импорта из корня `DeepSemantic`.

```sh
docker compose run --build --rm arxiv-grabber --from 2023-06-05 --to 2023-06-05 --query 'cat:cs.AI'
```

Обе даты включены. Отбор идёт по дате первой подачи статьи на arXiv в UTC. При пустом фильтре берутся все категории. Бакет по умолчанию — `arxiv-papers`, его можно изменить переменной `RUSTFS_BUCKET`.

## Формат источника

Переменная `ARXIV_SOURCE_FORMAT` действует для фонового воркера и прямого импорта.

- `pdf` (по умолчанию) сохраняет `arxiv/<arxiv_id>.pdf` и извлекает текст со всех страниц через `pypdf` в `arxiv/<arxiv_id>.txt`. В PDF без текстового слоя для извлечения текста потребуется OCR. Чанки содержат до 1000 символов с перекрытием в 150 символов. [Документация pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)
- `html` сохраняет `arxiv/<arxiv_id>.html` и собирает `arxiv/<arxiv_id>.md` через Beautiful Soup и markdownify. Markdown включает заголовки, LaTeX, подписи и ссылки на рисунки в arXiv, а также HTML-таблицы с объединёнными ячейками. В чанках сохраняются переносы строк. Большие таблицы делятся по строкам с повторением заголовков, если это допускает структура ячеек. Если arXiv не отдаёт HTML статьи, воркер записывает ошибку и продолжает обработку остальных статей.

Для фоновых заданий укажите `ARXIV_SOURCE_FORMAT=html` в `.env` и пересоздайте воркер командой `docker compose up -d --build arxiv-grabber`. Для разового импорта передайте `-e ARXIV_SOURCE_FORMAT=html` после `docker compose run --build --rm`.

Оригинал и полный извлечённый текст хранятся в одном бакете в RustFS. Воркер повторно использует скачанный исходник и текст, если ETag источника совпадает. Фрагменты хранятся в `chunks.text`, а их связь со статьёй и порядок — в `paper_chunks`. При повторном импорте в тот же бакет с другим форматом воркер заменяет каталог и чанки после успешного извлечения. При ошибке переключения используется прежняя версия.

## Каталог в pgAdmin

Каталог также доступен через API. `GET /papers?limit=20&offset=0` возвращает последние загрузки, `limit` принимает значения от 1 до 100. `GET /papers/{arxiv_id}` возвращает запись указанной версии статьи. Например, `GET /papers/2611.07253v1`. [Swagger UI](http://127.0.0.1:8000/docs#/papers)

Откройте **DeepSemantic PostgreSQL → Databases → deepsemantic → Schemas → public → Tables → arxiv_papers**. Если pgAdmin уже открыт, обновите узел **Tables**. [pgAdmin](http://127.0.0.1:5050)

```sql
SELECT arxiv_id, arxiv_import_id, title, submitted_at, bucket, object_key, text_object_key, downloaded_at
FROM public.arxiv_papers
ORDER BY downloaded_at DESC, arxiv_id;
```

`arxiv_import_id` ссылается на задание, при котором текущая копия исходника попала в каталог. Повторное использование той же копии сохраняет эту связь. Для старых записей и копий, добавленных через CLI, поле равно `NULL`.

Строка появляется после подтверждения, что исходник есть в RustFS. `arxiv_id` включает версию статьи и является первичным ключом. `submitted_at` — дата и время первой подачи, `downloaded_at` — время загрузки объекта в бакет по данным RustFS. `object_key` указывает на PDF или HTML. `text_object_key` указывает на TXT или Markdown в том же бакете и заполняется после сохранения извлечённого текста. При импорте той же версии в другой бакет каталог указывает на копию с более свежим `downloaded_at`. При равенстве времени выбирается бакет, который идёт первым по имени. Поля счётчиков API `pdf_available`, `pdf_reused` и `pdf_failures` сохраняют имена и отражают состояние исходников.

Запросы к arXiv выполняются последовательно с интервалом не менее трёх секунд. Для массовой загрузки архивов arXiv предоставляет [доступ к PDF через S3](https://info.arxiv.org/help/bulk_data_s3.html). [Руководство по API arXiv](https://info.arxiv.org/help/api/user-manual.html) · [Условия использования API](https://info.arxiv.org/help/api/tou.html).
