# arXiv Grabber

## Запуск через API

Из корня проекта запустите `just up`, затем включите скачивание, извлечение текста и суммаризацию на странице «Воркеры». Чтобы обновить миграции и API и сразу запустить воркер, выполните `docker compose up -d --build migrate api arxiv-grabber arxiv-text-worker summary-worker`.

Перед применением миграций `0019_drop_arxiv_import_result` или `0027_arxiv_import_attempts` дождитесь окончания текущего импорта и выполните `docker compose stop api arxiv-grabber`. Затем запустите миграции и новые версии сервисов командой выше.

```powershell
$body = @{
    date_from = '2023-06-05'
    date_to = '2023-06-06'
    query = 'cat:cs.AI'
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/arxiv/imports' `
    -ContentType 'application/json' -Body $body
```

`POST /arxiv/imports` принимает даты в формате `YYYY-MM-DD`, необязательные `bucket` и `query`. API возвращает `202 Accepted` и `{"id":"…"}` после записи задания в PostgreSQL `arxiv_imports`. При неверных параметрах API возвращает `422`, при недоступности PostgreSQL — `503`.

Воркер `arxiv-grabber` проверяет PostgreSQL каждые три секунды, пока очередь пуста. При старте задания он ставит `running` и продлевает двухминутную аренду каждые 30 секунд. После истечения аренды задание можно взять повторно. При ошибке обработки воркер повторяет задание через минуту. Максимум три попытки. Статус задания хранится в `arxiv_imports`. Подробности ошибок доступны в `docker compose logs arxiv-grabber` по ID из ответа API. `completed` означает, что задание скачивания завершено. Статьи появляются в каталоге со статусом `downloaded` по мере сохранения исходников.

На странице импорта «Приостановить» ставит задание из очереди на паузу сразу. Воркер завершает обработку текущей статьи перед паузой активного задания. «Продолжить» возвращает задание в очередь с тем же номером попытки. Команды доступны через `POST /arxiv/imports/{id}/pause` и `POST /arxiv/imports/{id}/resume`.

Маршрут также доступен в [Swagger UI](http://127.0.0.1:8000/docs).

`GET /arxiv/imports` получает счётчики из `arxiv_import_result(id)` и возвращает их в `result`. После поиска воркер записывает число найденных статей в строку попытки, затем обновляет счётчики и прогресс после каждой статьи. Пока поиск ещё ни разу не завершился, `result` равен `null`.

При возобновлении воркер заново запрашивает список у arXiv и проверяет наличие исходников сохранённого формата в бакете. Уже скачанные файлы он переиспользует. После поиска воркер начинает отсчёт прогресса для нового списка.

## Запуск через CLI

Команда для прямого импорта из корня `DeepSemantic`.

```sh
docker compose run --build --rm arxiv-grabber --from 2023-06-05 --to 2023-06-05 --query 'cat:cs.AI'
```

Обе даты включены. Отбор идёт по дате первой подачи статьи на arXiv в UTC. При пустом фильтре берутся все категории. Бакет по умолчанию — `arxiv-papers`, его можно изменить переменной `RUSTFS_BUCKET`.

## Формат источника

Переменная `ARXIV_SOURCE_FORMAT` действует для фонового воркера и прямого импорта.

- `html` (по умолчанию) сохраняет `arxiv/<arxiv_id>.html`. Если arXiv отвечает `404` со страницей об отсутствии HTML-версии статьи, воркер пропускает её без повтора задания. Число таких статей сохраняется в `result.html_unavailable`.
- `pdf` сохраняет `arxiv/<arxiv_id>.pdf`. Новые PDF остаются в каталоге со статусом `downloaded`.

`arxiv-text-worker` берёт готовые к обработке HTML со статусом `downloaded` и повторно захватывает `texting` с истёкшим `lease_until`. При захвате воркер ставит `texting` и выдаёт аренду на пять минут. Он сохраняет Markdown в том же бакете, записывает его ключ в `text_object_key`, ставит `texted` и очищает аренду. Если извлечение завершилось ошибкой, воркер возвращает статью в `downloaded`, очищает аренду и откладывает повтор через `text_available_at`.

`summary-worker` создаёт связанную запись в `paper_summaries` для статьи со статусом `texted` и Markdown. Ранее созданные чанки доступны для поиска.

## Каталог в pgAdmin

Каталог также доступен через API. `GET /papers?limit=20&offset=0` возвращает последние загрузки, `limit` принимает значения от 1 до 100. `GET /papers/{arxiv_id}` возвращает запись указанной версии статьи. Например, `GET /papers/2611.07253v1`. [Swagger UI](http://127.0.0.1:8000/docs#/papers)

Откройте **DeepSemantic PostgreSQL → Databases → deepsemantic → Schemas → public → Tables → arxiv_papers**. Если pgAdmin уже открыт, обновите узел **Tables**. [pgAdmin](http://127.0.0.1:5050)

```sql
SELECT arxiv_id, arxiv_import_id, title, submitted_at, bucket, object_key, text_object_key, downloaded_at
FROM public.arxiv_papers
ORDER BY downloaded_at DESC, arxiv_id;
```

`arxiv_import_id` ссылается на задание, при котором текущая копия исходника попала в каталог. Повторное использование той же копии сохраняет эту связь. Для старых записей и копий, добавленных через CLI, поле равно `NULL`.

Строка появляется после подтверждения, что исходник есть в RustFS. `arxiv_id` включает версию статьи и является первичным ключом. `submitted_at` — дата и время первой подачи, `downloaded_at` — время загрузки объекта в бакет по данным RustFS. `object_key` указывает на PDF или HTML. `text_object_key` указывает на TXT или Markdown в том же бакете и заполняется после сохранения извлечённого текста. При импорте той же версии в другой бакет каталог указывает на копию с более свежим `downloaded_at`. При равенстве времени выбирается бакет, который идёт первым по имени. Поля счётчиков API `pdf_available`, `pdf_reused` и `pdf_failures` сохраняют имена и отражают состояние исходников.

Запросы к arXiv выполняются последовательно с интервалом не менее трёх секунд. Для массовой загрузки архивов arXiv предоставляет [доступ к PDF через S3](https://info.arxiv.org/help/bulk_data_s3.html). [Руководство по API arXiv](https://info.arxiv.org/help/api/user-manual.html) · [Условия использования API](https://info.arxiv.org/help/api/tou.html).
